## 证据和解释边界

180 项均有实际终态来源、Root 独立复核和内容补充。150 项通过调用审计，
30 项调用审计失败。冻结评分器将失败审计来源列为 `reviewPending`，
两组分别为 10、20；这不表示缺少 Root 复核，也不能将其改为通过审计。
166 项机器读取回执获验证。初始加密启动消息的实际字节不可观察，
因此不认证所有位置均成功完成精确传输。

额度耗尽、调用路径错误和实际中断均保留为负面位置；没有在同一实验中重跑。
两组受影响程度不同，不能用完成位置重新归一化后推导质量提升，
也不能把总差异直接归因为业务验证功能。耗时按保留记录报告；
外部中断和模型调度使其不适合直接推导生产环境提速。

## 已交付能力

Core 根据已发布语义资产生成 `BusinessEvidenceV1`，通过 RPC `query.evidence`、
MCP `semarail_get_query_evidence(query_id)` 和 Console 独立读取。
证据展示单位、快照或期间、粒度、默认条件、确认状态及有限验证结果；
未定义的币种和评分尺度保持未定义。

`executionChecks` 在现有规则中维护并发布，准备与执行绑定调用者、SQL 摘要、
数据源、语义版本及规则版本。强制冲突或无法证明时阻止执行；
非强制未知条件标为未验证。有限验证覆盖声明的业务约束，
不证明自然语言意图与任意 SQL 完全等价，也不覆盖完整 SQL 表达式语法。

Console 在现有问题详情展示口径依据及修复关联，连接反馈、修订资产、发布版本、
回归用例版本、SQL 回归和经审核的外部 Agent 摘要。
单独 SQL 通过显示查询回归通过；完整已验证状态还要求同版本的外部证据获审核。
证据独立保留 30 天，读取重新校验权限，跨用户和撤权读取受限。

[技术验收记录](business-trust-v1-correction-acceptance-alpha9.json)保留
Console 344 项、Web 168 项、契约 20 项、隔离验证器 48 项检查，
类型检查及真实 PostgreSQL 存储验收通过。
正式评测前的真实认证验收包括两组各 60 条历史回归、60 项 Context、
21 项业务检查、4 项日期分组确认反例、30 题 Oracle，以及 18 项计划权限
和 18 项执行权限边界检查。这些属于技术证据，与回答质量结论分开。
